# apps/web

React Router v8 framework mode, `ssr: false`, prerendered, served by Workers Static Assets (ADR-0001, ADR-0013). Read `ARCHITECTURE.md`, ADR-0011, ADR-0012 and `DESIGN.md` before you change a screen.

- UI uses Tailwind utilities from `@vaultme/tokens` only (`theme.css`, `tokens.css`). No arbitrary values, raw colors or numeric styles (`scripts/check-repo-rules.sh` R2, R5, ESLint). A Figma size with no token goes in `app/app.css` as a `@utility` built from token values, with a removal note.
- Each file in `app/shared/ui` starts with `// Figma: <component> <node id>` (R6). Screens are route files in `app/routes`; copy comes from `@vaultme/i18n/web` (ko and en).
- A page ships no app JS unless its route sets `handle = { hydrate: true }` (`app/root.tsx`). The inline theme script (`app/shared/lib/theme.ts`) is the only script on static pages, and `scripts/finalize.ts` puts its sha256 in the CSP. Change the script and the hash follows at build time.
- The landing page is `app/routes/landing.tsx` (ko `/`, en `/en`, one component). Its head (canonical, hreflang, OG, JSON-LD) is JSX in the route (React 19 hoists it). `public/sitemap.xml` and `robots.txt` are hand-written with the production origin (`app/shared/lib/seo.ts`); `test/landing.test.tsx` checks they match the pages. The hero image is `AppMockup` (2x AVIF/WebP, the one `fetchpriority=high`). Store buttons stay inert until `app/shared/lib/stores.ts` gets real URLs (TODO(release)). The FAQ is native `<details>`.
- The viewer is `app/routes/address.tsx` (`/address`, `/en/address`, `hydrate: true`). The address lives in the URL fragment, a fragment-only change runs no route loader, so balances load in a hook (`app/shared/api/useBalances.ts`) through `@vaultme/api-client` with an install key made in the browser (`webSigner.ts`, ADR-0011). History (#196) and the transaction page (#197) are in progress or not built.
- Unknown paths answer a real 404 (ADR-0013). Do not add a SPA fallback.
- Gates: `pnpm --filter @vaultme/web test` (Vitest), `test:e2e` (Playwright + axe, needs `pnpm --filter @vaultme/web build`), `lhci` (Lighthouse CI, needs Chrome). Budgets live in `lighthouserc.desktop.json` and `lighthouserc.mobile.json`: the 100 KB JS budget covers static pages only (ADR-0012 limits the landing JS); the hydrated viewer pages (`/address`) have no JS budget assertion yet (`lighthouserc.*.json` skips `resource-summary:script:size` for them), and the owner has not set one. The viewer history list is `app/shared/ui/HistorySection.tsx`: 5 rows first, 더 보기 reveals 10 and asks for the next page, and every state keeps the skeleton height (`min-h-history-body`). Lighthouse covers the `/address` form only (the viewer needs an API); the history list is checked by `e2e/history.spec.ts` with fixtures. `@vaultme/history` and the API client load on the first read (`app/shared/api/useHistory.ts`).
- Build env: `WEB_API_ORIGIN` (CSP connect-src, default the staging API) and `WEB_ENV=production` (only then no `X-Robots-Tag: noindex`). Production builds are not set up yet.
- `test/build.test.ts` builds a fixture app (static index, hydrated route, 404). It guards the hydrate detection in `app/root.tsx`, which uses React Router's `UNSAFE_FrameworkContext`.
- Links and buttons are at least 44 px (`p-3 -m-3` or `min-w-touch-min`); the e2e spec checks every one.
- UI work follows the `vaultme-design-to-code` skill: light and dark comparison images at 375, 768 and 1280 in the PR.
- Fonts: `app/fonts.css` loads after first contentful paint (the inline script turns it on), so the Korean subsets (~270 KB) are not on the critical path. A `font-display: swap` stylesheet that loads before paint dropped mobile Lighthouse for the ko 404 to 92-96. Preloading a subset has the same effect, so there is none.
- PR previews are off (`web-preview.yml` removed, staging `preview_urls: false`) until a narrow-scope Cloudflare token exists: the `staging` environment has no branch policy, so a PR workflow would get the staging token. Cloudflare is checked before the staging deploy instead (`web-staging` job `gate`). Staging is served at `vaultme-staging.stack-line.dev` (custom domain in `wrangler.jsonc`).
