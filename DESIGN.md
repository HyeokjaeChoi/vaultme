# VaultMe design system

## Overview

VaultMe is a self-custody wallet for the Ethereum Sepolia testnet. It is a learning and portfolio project. It holds test funds only.

The UI must make the user read the account, network, asset, recipient or spender, amount or allowance, estimated fee and status before they sign. Calm and plain beats clever. The UI never claims a security check, network or feature that the app does not implement and verify.

Source order:

1. Figma (`NMXrn0q75G1SX2Bn1L1jP8`) is the source of truth for screens and components. This file does not describe single components.
2. `packages/tokens/tokens.json` is the source of token values. `packages/tokens/build.mjs` builds the app tokens from it.
3. This file holds the rules that cross components. `packages/tokens/design-md.mjs` generates the front matter from the token JSON. Do not edit it by hand: run `node packages/tokens/design-md.mjs --write`. A test fails when it is stale.

Token layers: Primitive holds raw values. Semantic aliases Primitive by role. Component aliases Semantic. App code uses `@vaultme/tokens` only. A new raw value goes in Primitive only.

Dark mode: the app follows the OS setting. There is no in-app toggle. The front matter shows the light theme. See "Colors" for dark.

The product language is Korean. Terms are in `CONTEXT.md`.

## Colors

The theme is light and quiet. White and pale grey surfaces carry data. One blue carries action.

- **Primary (#3152FF):** The action blue. See the rules below for where it may appear. Hover is #2944DB. Pressed is #2138B8. Text on it is white.
- **Secondary (#DCE8FD):** A pale blue tint for selection and soft emphasis. Text on it is Ink.
- **Neutral (#11161D, "Ink"):** Main text, and the colour of links. The Neutral ramp (0 to 950) builds all surfaces, borders and secondary text.
- **Canvas (#F6F8FB):** The page backdrop behind white surfaces.
- **Status:** Success is teal. Warning is amber. Danger is red. Info and Unknown are neutral. Each has a foreground, a tint background and a border.

Rules:

- Blue is an action colour. Never use it for success, price gain or safety.
- One Primary button per surface. A page is one surface and an open sheet is another. The page behind a sheet sits under the scrim and does not count.
- Blue appears only on: the Primary button, the selected bottom tab (stroke, icon and label), the input focus border and caret, an "on" switch track, a checked checkbox, and the brand tile on the lock and start screens.
- Failure and warning states use status colours, not blue. A screen whose Primary button is disabled has no blue.
- Links are Ink with an underline. They are not blue.
- Chips are neutral, including the Sepolia network chip. A chip is never amber, blue, green or red.
- Status colours appear only on status badges and warnings. A received amount is Ink with a "+" sign. A sent amount is Ink with a minus sign. Do not read them as profit or loss.
- Colour never carries meaning alone. Pair it with an icon, a label and a reason.
- `check.clear` means "the checks that ran found no problem". It uses a neutral surface. Only a confirmed outcome uses `status.success`.
- Blue text on the Secondary tint gives 4.4967:1. This fails the 4.5:1 text target. Use Ink there.
- Contrast targets: 4.5:1 for normal text, 3:1 for controls and focus. Static contrast does not prove WCAG or screen reader support.
- Disabled Primary is `surface.disabled` with `text.disabled`.
- Landing-page artwork and the dark closing call to action belong to marketing. They are not product themes.

Dark theme: `semanticDark` overrides `semantic` for surface, text, icon, border, status and a few more roles. Component values follow by alias. Canvas is neutral 950. Default surface is neutral 900. Raised surface is neutral 800. Primary text is neutral 50. Brand blue does not change. Dark status tints use the 950 steps of red and amber for body-text contrast. `frontMatter(tokens, 'dark')` in `packages/tokens/design-md.mjs` gives the dark values for tools.

## Typography

The UI uses **Pretendard** (400, 500, 600) for text. It uses **IBM Plex Mono** for addresses, hashes and facts. Weight 700 is only for the large figure (`figure`, a balance or an amount).

- **Figure:** 44/52, weight 700. Use it for one balance or one amount per screen. The unit beside it is `figure-unit`, 24/32, weight 600, secondary colour.
- **Display and titles:** `display-l`, `display-m`, `title1` to `title3`. Weight 600.
- **Headline:** 17/25, weight 600. Buttons and notice titles.
- **Row title:** 17/25, weight 500. Asset, activity and settings rows.
- **Body and label:** `body` 16/24, `body-small` 15/22, `label` 14/20. Money-out sentences use `body-small` in Ink. They are the most visible sentences on the screen.
- **Caption:** 12/17. Only for small support text.
- **Address:** 14/20 mono. Always show the full address.
- **Fact and fact-upper:** 12/16 mono. Use them for facts: network, chain ID, block, hash, version, time. Feelings and explanations use the sans face. `fact-upper` is uppercase, for English fact lines.

Rules:

- Letter spacing is negative at every size, because it suits Hangul. The front matter shows it in `em`. The token JSON stores percent.
- Show numbers with tabular figures where the platform allows it. Right-align them and show the unit.
- Never cut an amount with an ellipsis. If a long name and a value collide, move the value to the next line.
- Show tiny amounts with full precision on the review screen. Never show a rounded zero.
- Fee, address and error text is 14 px or larger.
- Show the same fact once. Do not repeat the big number in the first row. Use at most one chip per screen.

## Layout

The grid is a 4 px scale. The app is mobile first.

- Screen padding is 16. Section gap is 24. Group gap is 16. Row gap is 12. Field gap is 8.
- Asset rows have a minimum height of 64. Activity rows have a minimum height of 80. Heights grow with content. Never fix the height of a row that holds an address, a permission or a backup note.
- A row has an icon slot (32), a 12 gap, a body that fills, a value that hugs, and an accessory slot (20).
- Every touch target is at least 44 by 44 px. Visible control heights are 36, 44 and 52. Pill buttons are 40, 48 and 56.
- Review and result screens use a 12 px band in the canvas colour between sections. Home and Activity are white.
- Wide screens (future web): content max 1200, review panel max 480, tablet content max 704. Tables become stacked items with labels on narrow screens.
- Keep the scroll body apart from a fixed footer. The footer never covers an address or a warning.
- Design space on purpose. Use one rest area per screen. Put amount, chip, keypad and call to action in one column in the thumb zone.

Motion:

- Motion tokens are 120 ms (fast), 160 (exit), 200 (base), 240 (enter) and 320 (slow). Use ease-out. Do not exceed 250 ms for common paths.
- Frequent things do not move (the keypad). Rare moments may move (confirm, unlock).
- Selection changes show at once. Amounts, addresses and warnings never use blur, bounce or stagger.
- With reduced motion on, show the final state and remove transforms.

## Elevation & Depth

The product is flat. Depth comes from the surface colour, spacing and type, not from shadow.

- Surfaces: Canvas, then white `surface.default`, then white or neutral-800 `surface.raised` (dark) for sheets. `surface.subtle` and `surface.inset` give quiet wells.
- Lists, fields, review groups and notices have no shadow.
- Only a floating dialog or popover uses a shadow: `elevation.md` (0 8 24, Ink at 10%). `elevation.sm` and `elevation.lg` exist in Primitive.
- A modal uses a scrim: neutral 950 at 40% opacity. A nonmodal popover has no scrim. A scrim is not a theme.
- No gradient, glow, texture or decorative illustration on product surfaces.
- A small temporary toast may use the inverse surface. Information needed to judge a transaction stays on a light reading surface, never in a toast.

## Shapes

Shapes are soft but not playful.

- Buttons and chips are pills (`full`).
- Inputs and controls use `md` (12). Groups and notice banners use `lg` (16). Overlays and sheets use `2xl` (24). Rows have no radius.
- Do not mix sharp and rounded corners on one screen.
- Borderless is the default for containers and rows. Group by type, alignment and spacing. Do not fill the space left by a removed line with a shadow or a large gap.
- A line must have a job. Allowed jobs: an editable input, focus, invalid or selected state, a dense table comparison, a fixed footer or toolbar over a scroll body, a drawer edge. You must be able to say what the line separates.
- Account and network choices keep a check, a label and a selected surface. Do not mark selection by colour alone.
- Never set `border: 0`, `outline: none` or transparent colours globally. Border colour tokens stay. Border width is set by role aliases (none or hairline).
- The focus ring is 3 px with a 2 px offset. It stays visible for keyboard users.

Icons:

- Function and status icons are **Solar** (`@solar-icons/react-native`). Linear is the default. Bold marks the selected tab and status badges. Bold Duotone is for empty-state and result heroes (48 px). Do not mix icon libraries.
- Asset identity (ETH, USDC) is a separate original colour SVG. Never recolour it to the action blue. Show a neutral fallback for an unknown asset.
- Sizes: inline 16, control 20, feature 24, asset 32.
- Money actions have an icon and a visible label. A tooltip alone is not enough.
- An icon beside a label is `aria-hidden`. An icon-only control has an accessible action name and a 44 px target. Example: "Copy recipient address".
- A wallet, lock or check icon is not a certification or a safety guarantee.
- Solar is CC BY 4.0. Show the credit "Icons by 480 Design, Solar Icon Set, CC BY 4.0. Changes were made: resized and recolored." in the licenses screen.
- Do not animate icons on amounts, warnings or confirm actions.

## Components

Figma is the source of truth for each component. Use the most specific Component token. Use a Semantic token if there is none. The `components` front matter lists only a small cross-section. Preserve Figma node, master and property IDs.

Review anatomy. Every wallet action shows these items in this order:

1. The action, the account and the network. For a dApp action, also the origin.
2. The value to decide: the amount to send or the approval limit.
3. The asset identity and the full recipient or spender address.
4. The estimated network fee in the native asset. A fiat value is only an extra estimate.
5. The total deduction or the meaning of the permission. Never add different assets into one sum.
6. The check result with its reason, scope and time. Show the raw detail on request.
7. Cancel, and a Primary action with its exact label.

Review kinds differ. Do not force fee or allowance into a review that has none.

- Connection: origin, accounts, network scope and the data shared. It grants no allowance.
- Message signing: the parsed fields or the raw payload. If the payload cannot be read, make Reject the safe choice and disable signing.
- Approval: token, spender, limited or unlimited scope, fee.
- Transaction: asset change, recipient, fee, result status.

State and action rules:

- Missing price: keep the token balance. Show "price unavailable". Never replace it with 0.
- Stale price: show how old it is and offer refresh.
- Expired fee estimate: block Continue until it is refreshed.
- Fee unavailable: say so, show the total as unknown, offer retry, and block signing.
- Unlimited allowance: explain that the spender can use future deposits until you revoke.
- Submitting, Pending, Included, Confirmed, Failed and Unknown are different states with different copy. Only a confirmed outcome shows success.
- Unknown result: look up the original transaction first. Do not offer "send again" first.
- Disconnecting an app does not revoke an allowance. Revoke is a separate on-chain transaction.
- "No issues found in available checks" is a neutral notice and no safety guarantee. A readable message and a good simulation are not safety guarantees either.
- Do not show a "Verified" badge without a verification system.
- Disabled controls say why, near the control.
- Loading keeps the button width and blocks repeat taps.
- Inputs have a label, helper or error text, and a link to the field through `aria-describedby` (web) or an accessible description (native). A wrapper shows the inner invalid state.
- Each state has its own fixed copy. Editable text (names, amounts) is separate from state copy.
- Never put a real recovery phrase or private key in any design, fixture or test. Only the public test vectors listed in `scripts/check-repo-rules.sh` R10.
- Do not add Buy, Bridge, Stake, Swap, hardware wallet, biometrics, certification badges, QR or charts to a screen unless the feature exists and Figma has a frame for it.

Accessibility: keep label and error text visible, keyboard order, 44 px targets and focus. A dialog host needs a title, initial focus, focus containment, Escape or close, and focus return to the trigger. Check Escape, focus return and 200% text size in a running build. Figma and contrast numbers alone do not prove accessibility.

Components in front matter: `button-primary`, `button-secondary`, `input`, `chip`, `badge-*`, `notice-banner`, `overlay`, `segmented-control`, `skeleton`. Their values come from `buttonB`, `input`, `chip`, `badge`, `noticeBanner`, `overlay`, `segmented` and `skeleton` tokens.

## Do's and Don'ts

- Do put the balance or amount in one big figure per screen.
- Do show full addresses, the native-asset fee and the status on every review.
- Do use Ink plus underline for links, and neutral for chips.
- Do show a reason with every warning, disabled state and error.
- Do start every visual change in Figma, then in the app.
- Do use `@vaultme/tokens` values only. `scripts/check-repo-rules.sh` enforces this.
- Don't use blue for success, gain or safety.
- Don't use more than one Primary button per surface (page or sheet).
- Don't hide a warning, an address or a fee in a tooltip, a toast or a hover state.
- Don't replace a missing price or fee with 0.
- Don't claim a check, a network or a feature that is not built and verified.
- Don't repeat the same fact twice on one screen.
- Don't add shadow, gradient or an extra border to fill space.
- Don't copy another product's palette. Reference products inform layout and states only.
