## 일관성 메모

- 전송 표현이 섞여 있어요. S23/S41은 "전송했어요", 나머지는 "보내기"예요. 프레임 이름에는 "송신"도 있어요 (S23+S50).
- 상태 용어가 달라요. S23/S41 "처리 중", 본문 "네트워크 처리를 기다리는 중이에요", S40 "확인 못 함", S41 "마지막 확인".
- 영어가 남아 있어요. "Testnet 자산"(S10N/S10R/S10P)은 다른 곳의 "테스트넷"과 달라요. passphrase, burn, Etherscan, chain, Ethereum 메인넷도 있어요.
- 같은 개념의 이름이 둘이에요. 프레임 이름은 "유사 주소", 화면 문구는 "비슷한 주소"예요.
- 주소 이름이 여러 개예요. 받기 주소 / 받는 주소 / 보낸 계정 주소 / 첫 계정 주소.
- 화면 문구에 가운뎃점 "·" 연결은 없어요. 프레임 이름에만 있어요. 상태 줄은 "상태: 처리 중"처럼 콜론을 써요 (S23, S41).
- 어미가 섞여 있어요. 버튼은 명사형("복구", "검토"), "-어요"("이해했어요", "다 적었어요"), "-하기"("새 지갑 만들기")가 함께 있어요. S91 제목만 명령형("앱을 업데이트하세요")이에요.
- 시안 흔적이 남아 있어요. S30 "임시 QR, 스캔 안 됨", S22 본문에 고정된 "09:41", S41 "마지막 확인 09:41".

### 해결됨 (2026-10-13, [ux-terminology.md](ux-terminology.md) 기준)

- 해결: 전송 표현. "전송했어요"를 "보냈어요"로, 프레임 이름 "첫 송신"을 "첫 보내기"로 바꿨다.
- 해결: "Testnet 자산"을 "테스트넷 자산"으로 바꿨다. 영어 용어 나머지(passphrase, burn, chain)는 2026-10-13 적용했다. Etherscan·Ethereum은 유지.
- 해결: 프레임 이름 "유사 주소"를 화면 문구와 같은 "비슷한 주소"로 바꿨다.
- 해결: 상태 용어. 처리 중 / 블록에 포함됨 / 확정 / 실패 / 확인 못 함 / 실행되지 않음으로 정했다. 화면은 이미 맞아서 바꾼 것이 없다.
- 해결: 어미 규칙. 동작 버튼은 명사형이나 "-하기", 동의 버튼만 "-했어요". 현재 버튼은 모두 규칙에 맞아 바꾼 것이 없다.
- 남음: 주소 이름(받기 주소 / 받는 주소 / 보낸 계정 주소 / 첫 계정 주소)은 역할이 달라 유지했다. 시안 흔적(09:41, 임시 QR)은 이번 범위가 아니다.

## Redesign B 수정안 (2026-10-16, 오너 승인)

- 새 기능은 없다. 가격, swap, 다른 네트워크 문구는 넣지 않았다.
- Pending·Included는 아직 끝난 것이 아니므로 "보냈어요" 완료 문구를 쓰지 않는다 (Foundation 계약 3: 예상, 처리 중, 확정, 실패, 확인 못 함을 구분). "보냈어요"는 Confirmed에서만 쓴다.
- 화면 ID: Redesign B는 S20을 두 단계로 나눈다. 이 절에서는 S20a(받는 주소), S20b(금액)로 쓴다. ux-flow의 S21(QR 스캔)과 겹치지 않게 하려는 임시 이름이다.

### S22 제목 결정

화면 제목 자리(헤더)에 "이대로 보낼까요?"를 쓴다. 별도의 "보내기 검토" 헤더는 두지 않는다.
- 이유 1: 화면당 제목 자리는 하나다. S20a·S20b와 같은 자리에 질문이 오면 세 단계가 같은 규칙으로 읽힌다.
- 이유 2: 첫 값이 금액 hero(Display M)로 유지된다. 질문 문장을 hero에 섞으면 금액이 전체 정밀도로 줄바꿈될 때 문장이 깨진다 (L00).
- 이유 3: "검토"라는 말은 S20b의 버튼 "검토"에 남아서 사용자가 지금이 검토 단계라는 것을 안다.
- Toss의 "…채울까요?" 문장형은 받는 사람 이름이 있을 때 맞는다. VaultMe는 주소만 있어 "OO에게 0.05 ETH를" 문장을 만들 수 없다.
- 비슷한 주소, 소각 주소, 토큰 컨트랙트 변형에서도 제목은 같다. 위험은 상태 제목("받는 주소가 의심스러워요" 등)과 확인 시트가 맡는다.

### 이 절에서 바꾸지 않은 것

- 위험 주소 시트와 경고 (S22L, S22B, S22T): 안전 문구라 그대로다. 제목은 위 질문형이 되지만 상태 제목과 시트 문구는 바뀌지 않는다.

### 오너에게 묻는 것

1. S20a·S20b 이름을 써도 되는지, 아니면 ux-flow의 ID를 새로 정할지.
2. ETH 금액 칩을 "전액" 하나로 할지, 25% / 50% / 전액으로 할지.
3. ETH "전액"은 잔액에서 최대 수수료를 뺀 값이다. 이 동작과 보조 문구에 동의하는지.
